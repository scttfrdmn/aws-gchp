C180 OFF-NODE, SEPARATE WORKER FLEET — remove the last co-location oversubscription — 2026-07-28
==================================================================================================
Two clusters: TRANSPORT gchp-s3c180tx (r8gn.24xl, 48 ranks, NO local workers, hardened slurm) +
WORKER FLEET gchp-s3pool (4x c7g.16xl = 256c/4 NICs, 48 s3_chem_workers). Fixed shared jobid
SEPFLEET1; chemistry served ENTIRELY by the separate fleet via chemq/SEPFLEET1/. No co-scheduling.

BASELINE (inline, on the r8gn transport): md5=9ea1a39d, RUN 12.9 d/d, wall 791s.

SEPARATE-FLEET OFF-NODE:
  md5=9ea1a39dcd0b04350288e79e06e35d58 == baseline  ✅ BYTE-IDENTICAL
  PUT failures = 0                                   ✅
  fleet solves = 133 slices, ALL on the separate cluster -> transport node did ZERO chemistry ✅
  RUN throughput = 12.8 d/d = 99% of baseline 12.9   ✅ (decoupling preserves compute-tier throughput)
  wall = 3051s  <-- CONTAMINATED, NOT a clean number (see below)

WHAT THIS PROVES (the architecture works end-to-end):
  Chemistry ran on a physically separate cluster (different nodes, own cores, own NICs, no EFA, no
  placement group, no shared allocation) and the result is byte-for-byte identical to inline. This is
  the actual production shape of off-node decoupling -- transport and chemistry decoupled in
  PROVISIONING, not just in code. Neither the m9g NIC-starvation nor the r8gn CPU-contention is present:
  the transport node's cores + NIC serve only the 48 ranks; the workers have their own 4 nodes.

WHY THE WALL IS CONTAMINATED (honest):
  Per-superstep wallclock stamps show a 19-MINUTE GAP on one chem step (sim 00:10->00:15 = wall
  06:26->06:45) while the other steps were ~instant. Cause = WORKER-FLEET LIFECYCLE, not decoupling:
  between the fast transport-only supersteps the workers saw no .in, counted idle polls, and fleet
  nodes began scaling down; when the chem step's 48 slices landed, only part of the fleet was alive and
  the rest had to resume (~2-3 min/node) -> stall. Plus the 3051s includes ~15-20 min of transport
  sitting blocked during my worker-launch churn (2 false starts: a 48-way boto3 install race into a
  shared --target dir -> all workers exit 3; then srun not surviving the non-interactive SSH -> fixed
  with a single pre-install + setsid/nohup/disown launch). So wall != a clean separate-vs-colocated ratio.

THE REAL LESSON: co-scheduling two INDEPENDENT clusters' lifecycles is fiddly. For a clean wall number
  the worker fleet must stay WARM and STABLE across the transport's slow + variable superstep cadence
  (C180 init ~30min; chem steps interleaved with fast transport steps). Fixes for a clean re-run:
  (1) pre-warm the fleet (MinCount>=1 or a keep-alive so nodes don't scale down between chem steps);
  (2) much longer worker idle-exit (or none, tear down manually);
  (3) start the fleet only AFTER the transport reaches its first superstep (or pin the fleet up for the
      whole run). None of these change the PHYSICS -- they're operational glue for the demo.

BOTTOM LINE: separate-fleet off-node decoupling is CORRECT (byte-identical), fully off-node (0 chem on
  transport, 0 PUT failures), and throughput-preserving at the compute tier (RUN = baseline). A clean
  wall-clock speedup number needs a warm/stable fleet; this run proved the architecture, not the wall.
  Co-location artifacts (m9g NIC / r8gn CPU) are GONE; the remaining variable is fleet warm-management.
